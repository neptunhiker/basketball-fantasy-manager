{% extends "partials/modal.html" %} {% comment %} A confirmation modal, driven entirely by context -- so a new one needs a view and no template at all. Subclass apps.core.views.TypedConfirmView and set the strings. Context: title, body, action_url, confirm_label, cancel_label, confirm_word, tone ("danger" or "primary"), error. `error` renders whether or not there is a word to type: a plain confirm can still be refused by whatever `perform` runs into. With `confirm_word` set the user has to type it out; the button stays disabled until they do. That is a courtesy, not the gate -- the view checks the typed value again server-side, because a disabled button stops nobody with a terminal. Leave it empty for a plain confirm. An empty `confirm_label` renders no confirm button at all, which is how a view says "this cannot be done, and here is why" through the same modal. {% endcomment %} {% block modal_title %}{{ title }}{% endblock %} {% block modal_content %}
